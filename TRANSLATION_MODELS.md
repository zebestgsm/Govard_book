# Какие модели подгрузить для перевода: короткий ответ и обоснование

Коротко: **подгружать в GitHub ничего не нужно**. Веса моделей не хранят в репозитории книги, и
GitHub для этого не приспособлен (лимит файла 100 МБ без LFS, 2 ГБ на файл с LFS, репозиторий
раздувается и клонируется всеми). Модель скачивается в CI из Hugging Face на каждом прогоне —
для публичных моделей токен не нужен.

Но один шаг «подгрузить» всё же есть: если вы готовы выложить модель **на свой аккаунт Hugging
Face** (не в GitHub), это снимает главный риск — что базовую модель удалят или переименуют и CI
встанет. Это 5 минут работы в веб-интерфейсе, без командной строки.

---

## 1. Что реально определяет качество результата

Работа у нас такая: машинный черновик → ручное редактирование. Поэтому:

| Что даёт прирост | Насколько | Почему |
|---|---|---|
| Чистый вход (склейка сегментов, снятие 32 колонтитулов, абзац вместо обрывка) | **очень много** | сейчас 25 % переходов между сегментами рвут предложение; модель переводит обрывок — получается «Крес-ТерФилд» и «провидец обычно прокладывал дыру в полу» |
| Глоссарий и постобработка терминов | **много** | 265 «gaol», 183 «gaoler», 199 «bridewell» — если термин один раз решён, он держится по всей книге |
| Модель побольше (300 MB → 1,2 GB) | умеренно | меньше грубых ошибок синтаксиса, но «гаолер» и «кран» всё равно останутся |
| LLM 7–8B с инструкцией «переводи дословно, не сглаживай» | заметно на стиле | лучше держит длинный период и терминологию, но на CPU медленно |

Вывод: **качество даёт не модель, а вход и редактирование**. Модель — второй по важности фактор.

---

## 2. Ограничения, которые надо учесть до выбора

1. **Песочница без сети до Hugging Face** — локально модель не запустить, только в CI.
2. **GitHub Actions — CPU, 2 ядра, 7 ГБ RAM, лимит задачи 180 минут** (сейчас так в `translate-ru.yml`).
   Замер по прошлому прогону: 6 549 предложений, 0,66 с на предложение → **~1,2 часа** на
   `opus-mt-en-ru` с `num_beams=4`. Для книги 122 тыс. слов это уже половина лимита.
3. **Модель 7–8B на CPU**: порядка 3–4 с на предложение при 4 потоках → **десятки часов**, то есть
   в один прогон не влезает, нужен GPU-раннер (платный) или разбиение на 10–15 прогонов.
4. **Стиль**: большие модели любят «причёсывать» текст. Для Говарда это вредно — в промпте нужно
   прямо запрещать сглаживание; маленькие модели этого не делают, но и терминологию не держат.

## 3. Модели: что брать и в каком порядке

### Уровень 1 — обязательно (уже используется, менять не нужно)

**`Helsinki-NLP/opus-mt-en-ru`**, ~300 МБ, Marian, BLEU 23,5–31,1 на newstest.
Работает на CPU, 1,2 часа на книгу, предсказуем. Это **черновик**, а не финал.

### Уровень 2 — стоит попробовать (замена той же модели, лучше качество)

| Модель | Размер | Ожидаемый эффект | Риск |
|---|---|---|---|
| **`Helsinki-NLP/opus-mt-tc-big-en-ru`** | ~1,2 ГБ | новее и больше (transformer-big, OPUS-TC 2021 + backtranslation), обычно заметно лучше на длинных периодах | на CPU ~3,6 часа; влезает в 180 минут, но с запасом небольшим |
| `Helsinki-NLP/opus-mt-en-ru` + `num_beams=5` | без изменений | дешёвый прирост качества, замедление ~20 % | нет |

### Уровень 3 — если нужен GPU (не бесплатно)

| Модель | Размер | Замечание |
|---|---|---|
| **`tencent/Hunyuan-MT-7B`** | 16,1 ГБ (BF16), есть fp8-вариант | лидер WMT25 в 30 из 31 языковой пары; лучший открытый переводчик en→ru на 2026 год; **на CPU нереалистичен**, нужен GPU-раннер |
| `facebook/nllb-200-distilled-600M` | ~2,4 ГБ | многоязычная, но на en→ru обычно слабее OPUS; смысла мало |
| `facebook/m2m100_1.2B` | ~4,8 ГБ | устарела на фоне Hunyuan, на CPU медленно |

### Уровень 4 — не для перевода

LLM общего назначения (Qwen, Llama, Mistral и т. п.) для **чернового перевода книги не нужны**:
они дают красивее звучащий текст, но систематически добавляют от себя, а нам нужна точность.
Их разумно использовать не как переводчик, а как **второго контролёра** — «сверь русский абзац
с английским и перечисли пропуски». Это можно делать без загрузки весов: по API или вручную.

## 4. Что и как «подгрузить», если хотите застраховаться

Сценарий: публичную модель могут удалить/переименовать → CI падает. Тогда вы делаете **свою копию
на Hugging Face**:

1. Войдите на huggingface.co → **New → Model**.
2. Имя, например: `ваш-логин/opus-mt-en-ru-copy` (можно private — бесплатный аккаунт даёт 100 ГБ
   приватного хранилища; публичные репозитории — best-effort без оплаты).
3. На странице модели: **Files → Add file → Upload files** — но проще кнопка **«Duplicate this
   model»** на странице `Helsinki-NLP/opus-mt-en-ru` (Files and versions → ⋯ → Duplicate). Копия
   создаётся в один клик, веса не перекачиваются через ваш браузер.
4. В репозиторий книги ничего не кладём. В `tools/translate_opus.py` меняется одна строка:
   `name='ваш-логин/opus-mt-en-ru-copy'`.
5. Если модель приватная, в GitHub → Settings → Secrets → Actions добавить `HF_TOKEN`
   (read-only токен с huggingface.co → Settings → Access Tokens), а в workflow передать его
   в `hf_hub_download(..., token=os.environ['HF_TOKEN'])`. Для публичной копии токен не нужен.

То же самое для `opus-mt-tc-big-en-ru`, если решим его пробовать.

**Чего делать не надо**: заливать веса в GitHub-репозиторий (в том числе через Releases) — файл
1,2 ГБ упрётся в лимиты и раздуется история клона; держать модель в git-lfs внутри книги.

---

## 5. Моя рекомендация

1. **Не менять движок сейчас.** Сначала поправить вход (склейка абзацев, снятие колонтитулов,
   глоссарий в постобработке) и прогнать тот же `opus-mt-en-ru`. Это даёт основной прирост
   и ничего не стоит.
2. **Один эксперимент**: на 3–4 разворотах (31, 87, 141, 95) сравнить `opus-mt-en-ru` и
   `opus-mt-tc-big-en-ru` при одинаковом входе — по числам, терминам и читаемости. Это ~10 минут
   CI на модель. По результату решаем, какая идёт в основной прогон.
3. **Копию выбранной модели положить на свой HF-аккаунт** (Duplicate в один клик) — страховка от
   удаления и от лимитов анонимных скачиваний.
4. Hunyuan-MT-7B держать в уме как вариант «если понадобится GPU и максимальное качество
   черновика» — но при ручном редактировании выигрыш не оправдывает ни оплату раннера, ни
   десятки часов.
