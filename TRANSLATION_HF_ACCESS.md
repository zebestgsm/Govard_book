# Доступ к Hugging Face: три варианта и что из них реально работает

Требование: **максимально полный перевод с учётом разных лексических норм**. Это достижимо,
но не одним нажатием «привязать HF» — ниже честно о том, что даёт доступ, а что нет.

---

## 1. Главное ограничение (проверено заново)

Из этой песочницы **нет сети до huggingface.co**: `curl -sI https://huggingface.co` возвращает
пустой ответ, `argostranslate` не может скачать индекс моделей, `pip download torch` с
`download.pytorch.org` не находит пакет. Работают только `pypi.org`, `github.com` и `api.github.com`.

Следствие: **токен HF не поможет** — проблема не в правах, а в сетевом маршруте. Даже с вашим
токеном я не смогу скачать модель внутри этой сессии. Поэтому привязка HF к песочнице
бесполезна, и я не буду просить у вас токен: он всё равно не решит задачу.

Что действительно работает: **GitHub Actions** — там сеть до HF есть, и именно там уже стоит
`translate-ru.yml` с OPUS-MT.

---

## 2. Три способа дать мне HF-возможности

### Вариант A. Ваш токен в GitHub Secrets (рекомендую)

Ничего не привязываем к песочнице. Токен хранится в самом GitHub, где и будет идти работа.

1. huggingface.co → **Settings → Access Tokens → New token**, тип **Read**, имя `govard-ci`.
   Скопируйте `hf_...`.
2. GitHub → репозиторий `zebestgsm/Govard_book` → **Settings → Secrets and variables → Actions
   → New repository secret**: имя `HF_TOKEN`, значение — токен.
3. В workflow я добавляю одну строку `HF_TOKEN: ${{ secrets.HF_TOKEN }}` — и модель скачивается
   в CI от вашего имени (это снимает лимиты анонимных скачиваний и даёт доступ к вашим копиям).

Токен **не попадает** ни в код, ни в логи, ни в чат. Мне его присылать не нужно.

### Вариант B. Вы выкладываете нужные модели на свой HF-аккаунт

Полезно как страховка от удаления и как «своя» копия для CI: *Duplicate* в один клик на странице
модели. В коде меняется только имя модели. Подробности — в `TRANSLATION_MODELS.md`.

### Вариант C. Вы прогоняете модель у себя и присылаете файл

Если хотите использовать модель, которой нет смысла гонять в CI (например, 7–8B на своей машине):
прогоняете её на `translation_sources/work-doc.json` (его готовлю я, склейка абзацев),
присылаете JSON вида `{номер разворота: текст}` — я встраиваю как черновик, дальше ручное
редактирование и проверки. Этот путь **не требует никакой привязки** и даёт лучший черновик.

---

## 3. Что значит «максимально полный перевод с учётом лексических норм»

Здесь важное различие, которое стоит зафиксировать, потому что от него зависит выбор модели:

| Что нужно | Чем достигается |
|---|---|
| Полнота: ни одного пропущенного абзаца, числа, сноски | вход из выверенного текста (165 разворотов, 891 сегмент) + проверки чисел/сносок/латиницы |
| Разные лексические нормы: один и тот же термин не гуляет | **глоссарий** (уже создан: 133 статьи) + автоматическая проверка запрещённых вариантов |
| Разные регистры: канцелярский отчёт, юридический текст, моралистическое отступление, цитата из статута | правила по регистрам (§4) и разная стратегия для прозы и таблиц |
| Отсутствие отсебятины | правило «ничего не добавлять», обратный перевод 1 из 10 разворотов |

Модель влияет только на качество черновика. Лексическую норму задаёт глоссарий, а не модель.

---

## 4. Лексические нормы: что уже сделано и что будет

- `translation_glossary.json` — **133 статьи**: `en`, основной русский вариант, допустимые
  варианты, запрещённые варианты, примечание. Примеры:
  - `gaol` → «тюрьма» (запрещено «гаол»); `county gaol` → «тюрьма графства» (запрещено «уездная»);
  - `gaoler` → «тюремщик», допустимо «смотритель»/«надзиратель» (запрещено «гаолер»);
  - `bridewell` → «исправительный дом» (запрещено «бридвелл»);
  - `felon` → «уголовный заключённый» (запрещено «фелон»);
  - `transportation` → «ссылка» (запрещено «перевозка», «транспортация»);
  - `garnish` → «вступительный побор», `chummage` → «плата за место среди товарищей»;
  - `tap` → «тюремный кабак» (запрещено «кран»);
  - `allowance` → «довольствие», `fee` → «побор», `salary` → «жалованье»;
  - `sessions` → «сессии», `assizes` → «выездные сессии» (запрещено «сеанс», «ассизы»);
  - `gaol-fever` → «тюремная горячка» (допустимо «тюремный тиф» с пояснением).
- `tools/glossary_check.py` — проверка после каждой порции: находит запрещённые варианты в
  готовом тексте и подсказывает, какие частые термины ещё не заведены в глоссарий.
- Дальше глоссарий растёт по данным книги, а не по догадкам: скрипт уже показывает очередь
  кандидатов (`prisoners`, `confined`, `fees`, `criminals`, `houses`…).

Три регистра, для которых будут отдельные правила:

1. **Отчёт Говарда** — короткие записи, единые формулы полей (`Allowance`, `Fees`, `Number`,
   `Bath`, `Infirmary`, `Chapel`, `Remarks`). Переводится формулой, одинаково во всех 42 разворотах округов.
2. **Юридический и статутный текст** — «вынесено присяжными», «постановлено судом»; архаика
   сохраняется, канцелярит не сглаживается.
3. **Моралистические отступления и цитаты** — длинный период, риторические вопросы, библейские
   обороты; здесь допустима более высокая архаизация («Одному Богу вся хвала!»).

## 5. Что предлагаю сделать сейчас

1. Вы создаёте `HF_TOKEN` (тип Read) в GitHub Secrets — 2 минуты, мне его присылать не нужно.
2. Я готовлю правку `tools/translate_opus.py` и workflow: вход — `work-doc.json` (склейка абзацев,
   колонтитулы вынесены), переключатель модели `MT_MODEL`, два прогона на 4 контрольных
   разворотах (`opus-mt-en-ru` против `opus-mt-tc-big-en-ru`), отчёт по числам и терминам.
3. По результату выбираем модель для полного черновика; глоссарий применяется к черновику
   автоматически (замена терминов + пометки для ручной проверки).
4. Полный черновик — 133 разворота, ≈1,2 ч (для `opus-mt-en-ru`) или ≈3,6 ч (для `tc-big`).
   Дальше идём порциями по 2–3 разворота: я редактирую, вы проверяете.

Если CI-путь по каким-то причинам неудобен — работает вариант C: вы прогоняете модель у себя,
я делаю склейку и все проверки. Скажите, какой путь выбираете.
